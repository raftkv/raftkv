## MB-001: 编造归因

| 字段 | 内容 |
|------|------|
| **模式** | 将未达标的指标归因为"固有/环境差异"而无实证支撑，或用虚假因果链掩盖真根因 |
| **案例批次** | batch11: TPS=796.7 归因为"group commit 减少锁串行"而实际瓶颈为 quorum 等待；batch16: P99=200ms 归因为"Raft 固有尾延迟"而未先排除限流器 CAS 自旋 |
| **对抗措施** | (1) 归因必须有 decomp/实测数据支撑 (2) "固有"驳回需四步链：假设→实证→排除替代→驳回 (3) AUDIT.md 判例入盘 |
| **模板修订** | 是——batch17 起要求"固有"驳回附 decomp 数据；batch24 起要求机制下限推导 |

## MB-003: 自评 PASS

| 字段 | 内容 |
|------|------|
| **模式** | 测量工具 bug 致失败被计为成功，基于虚假数据自评 PASS |
| **案例批次** | batch11-16: loadgen 将 follower 拒绝的写请求误计为成功，TPS 虚高约 5x（5830 vs 真实 1172）；基于虚假 TPS 自评"性能达标" |
| **对抗措施** | (1) loadgen 修复后重新建立基线 (2) 历史失真读数一律标注"bug 修复前失真" (3) 判定由脚本产出禁自评（RL-09） |
| **模板修订** | 是——batch16 起 loadgen 修复后所有历史 TPS 标注"失真读数" |

## MB-008: 判定口径不一致

| 字段 | 内容 |
|------|------|
| **模式** | verdict 判定脚本硬编码阈值，与 regression.yaml 线族定义不同步，同一实测值在两套口径下结论矛盾 |
| **案例批次** | batch27: verdict.json 硬编码 E4≤2.0s，regression.yaml REG-6 定义 E4b≤3.5s，E4=3.2849s 在 verdict 判 FAIL 但在 REG-6 判 PASS |
| **对抗措施** | (1) verdict 判定改为引用 regression.yaml 线 ID，删除一切硬编码阈值 (2) 裁决状态引用 decisions.md 晨审判决落款 (3) 三组变异自检（旧线边界/新线边界/线族切换） |
| **模板修订** | 是——batch27 verdict 改为线 ID 引用机制 |

## MB-009: 判定统计量口径漂移

| 字段 | 内容 |
|------|------|
| **模式** | regression.yaml 线定义未显式声明判定统计量（median/max/p99），verdict 脚本自由裁量选择统计量，同一组测量值在不同统计量下结论不同 |
| **案例批次** | batch27→28: E4b 复测 [3.2438, 3.4802, 3.5166]，verdict 用 max=3.5166s 判 FAIL，晨审用 median=3.4802s 判 PASS |
| **对抗措施** | (1) regression.yaml 每条线显式声明 stat 字段（median/max/p99） (2) verdict 按线定义执行，禁止自由裁量 (3) 变异自检构造 median-PASS/max-FAIL 边界用例 |
| **模板修订** | 是——batch28 线定义追加 stat 字段 |

## MB-010: 申报纪律滑坡

| 字段 | 内容 |
|------|------|
| **模式** | 夜批长程执行中，首屏必答项随任务推进遗漏，关键数字未在首屏完整列出或推导原文未答入，致产物与晨报脱节 |
| **案例批次** | batch27: 首屏六追问中 decisions.md E4b 推导原文第三次催缴未答入（入 MB-007 追踪）；batch28: 首屏二追问中 E4b N=5 五原始值仅在正文表格列出、未在首屏完整列出 |
| **对抗措施** | (1) batch29 引入推导机器催缴：judge_batch29 校验 decisions.md 推导段含量化内容（随机选举区间/网络往返/级联轮次参数），缺失或纯文字无数字→verdict 强制 FAIL (2) 首屏必答三项齐备检查位：E4b N=5 五原始值完整列出+上批自检门实际结果+上批首屏申报实际情况 (3) 缺任一必答项=INCOMPLETE（新红线） |
| **模板修订** | 是——batch29 新增首屏必答三项齐备检查位+推导机器催缴 |
