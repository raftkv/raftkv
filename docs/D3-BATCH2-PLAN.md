## 3. 用例定义

### E05 [起草] 基线TPS压测

| 项 | 内容 |
|---|---|
| **目的** | 测量5节点集群基线TPS，确定batch2正式目标值 |
| **步骤** | 1. 5节点集群正常运行<br>2. 通过leader并发写入，梯度加压：10/50/100/200/500并发<br>3. 每级持续60秒，记录TPS/成功率<br>4. 找到TPS拐点（成功率<99%或TPS不再增长） |
| **预期** | 产出TPS-并发曲线，确定基线TPS和拐点并发数 |
| **证据格式** | `E05/result.txt`: 各并发级TPS/成功率、拐点、建议目标值<br>`E05/tps-curve.csv`: 原始数据 |

### E06 [起草] 延迟P99/P50测量

| 项 | 内容 |
|---|---|
| **目的** | 测量5节点集群在基线TPS下的延迟分布 |
| **步骤** | 1. 5节点集群正常运行<br>2. 以E05确定的基线并发数持续写入120秒<br>3. 记录每请求延迟，计算P50/P90/P99/Max |
| **预期** | 产出延迟分布，P99和P50目标值[待定]（E06实测后按×0.8设目标） |
| **证据格式** | `E06/result.txt`: P50/P90/P99/Max、建议目标值<br>`E06/latency-hist.csv`: 延迟直方图 |

### E07 [起草] 长稳压测

| 项 | 内容 |
|---|---|
| **目的** | 验证5节点集群持续写入稳定性（零失败、无内存泄漏） |
| **步骤** | 1. 5节点集群正常运行<br>2. 以基线并发×0.8持续写入15分钟<br>3. 每30秒记录TPS/commit/内存<br>4. 检查：0失败、TPS无衰减、内存无持续增长 |
| **预期** | 15分钟0失败，TPS波动<10%，内存稳定 |
| **证据格式** | `E07/result.txt`: 总TPS/总条数/失败数/内存趋势/结论<br>`E07/timeline.csv`: 每30秒采样 |

### E08 [起草] 分区恢复高负载退化验证

| 项 | 内容 |
|---|---|
| **目的** | 验证高负载下分区恢复追平耗时是否退化（对比E02的35s基线） |
| **步骤** | 1. 5节点集群正常运行<br>2. 以基线并发持续写入<br>3. 断开一个follower网络<br>4. 持续写入10秒<br>5. 恢复网络，轮询追平耗时（上限120秒）<br>6. 对比低负载35s基线 |
| **预期** | 高负载下追平耗时 ≤ 35s × 负载因子（[待定]，E08实测后确定） |
| **证据格式** | `E08/result.txt`: 高负载追平耗时、与E02基线对比、退化比 |
