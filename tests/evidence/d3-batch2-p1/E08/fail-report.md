## 失败模式分析

### 时序

| 时段 | 失败数 | 描述 |
|------|--------|------|
| 0-80s | 0 | 无失败 |
| 85s | 9 | 首次失败出现 |
| 85-515s | 渐增至1,601 | 间歇性失败（选举抖动） |
| 520s | 1,601 | 大规模失败前夜 |
| 525s | 4,522 | **leader切换**（失败跳增） |
| 530s+ | 持续增长 | 切换后写入发往旧leader被拒 |

### 根因初判

失败由**leader切换**引起：
1. 5节点Docker bridge网络环境下，网络抖动导致Follower选举超时
2. Leader切换期间，写入请求发往旧Leader被拒（返回"not leader"错误）
3. 2h内多次leader切换，累积3.4M失败

### Max/P99分析

- Max=134.7ms（远<1s，长尾上界有效）
- P99=49.6ms（稳态延迟良好）
- 失败请求不贡献延迟统计，延迟指标仅反映成功请求
