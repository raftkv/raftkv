## 3. 偏差归因

TPS偏差-78.4%超出±15%，P99偏差+673%超出±15%。归因如下：

### 3.1 环境差异

| 维度 | 锚定环境(鲲鹏) | 本地环境 | 预期影响 |
|------|---------------|---------|---------|
| CPU | 鲲鹏920 ARM64, 多核 | x86_64, 18核 | TPS↓ 3-5x |
| 网络 | 原生网络 | Docker bridge(NAT) | 延迟↑ 3-5x |
| 主机OS | Linux | Windows Docker Desktop | 额外开销 |
| 架构 | ARM64 | x86_64 | 指令集差异 |

### 3.2 折算比

```
折算比 = 实测TPS / 锚定TPS = 7,877 / 36,461 = 0.216
```

该折算比反映本地Docker环境与鲲鹏实机的性能差距，作为后续E05/E07/E08的本地基线参照。

### 3.3 P99归因

P99=984.8ms vs 锚定127.4ms。主因：
- Docker bridge网络每跳增加~10-30ms延迟（NAT + veth）
- 5节点集群经bridge网络通信，每次Propose需quorum(3/5)确认
- P50=32ms反映基础延迟，P99长尾由GC/网络抖动叠加

### 3.4 Max归因

Max=2,357ms。R-03触发线=5s，未触发。Max长尾来源：
- Docker Desktop资源调度抖动
- Go GC stop-the-world（~100ms级）
- 网络重连瞬时（R-01修复后MaxDelay=5s）
